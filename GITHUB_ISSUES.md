# GitHub Issues

We use GitHub issues to track bugs, feature requests, and other tasks. Before opening an issue, please check if a similar issue already exists.

## Issue Types

### 🐛 Bug Report

A bug is something that doesn't work as expected.

**When to use**: When you find something that doesn't work correctly

**Title format**: `[BUG] Descriptive title`

**What to include**:
- Steps to reproduce
- Expected behavior
- Actual behavior
- Screenshots/logs
- Environment details

### ✨ Feature Request

A feature is a new capability or enhancement.

**When to use**: When you want to suggest a new feature

**Title format**: `[FEATURE] Descriptive title`

**What to include**:
- Use case
- Benefits
- Proposed solution
- Mockups (if applicable)

### 📚 Documentation

Documentation improvements for clearer, more helpful docs.

**When to use**: When documentation is unclear or missing

**Title format**: `[DOCS] Descriptive title`

**What to include**:
- What's unclear
- Suggested improvement
- Related links

### 🤔 Question

A question about how to use or contribute to the project.

**When to use**: When you need help or clarification

**Title format**: `[QUESTION] Your question`

## Labels

We use labels to categorize issues:

- `bug` - Something isn't working
- `feature` - New feature or request
- `documentation` - Improvements or additions to documentation
- `good first issue` - Good for newcomers
- `help wanted` - Extra attention is needed
- `in progress` - Currently being worked on
- `blocked` - Waiting on something else
- `priority: high` - Should be done soon
- `priority: low` - Can be done later
- `backend` - Related to backend code
- `frontend` - Related to frontend code
- `database` - Database-related
- `security` - Security concern

## Issue Templates

We provide templates to make creating issues easier. They appear when you click "New Issue" on GitHub.
